# 统一界面重构评估报告

> 日期：2026-09-12
> 背景：计划依据 `F:\workProject\personProject\myshell\docs` 的「统一界面方案」，使用 `myui@git+https://gitee.com/argustang/my-ui.git#v0.2.2` 对本项目前端进行界面重构。

## 1. 核心事实

### 1.1 myui v0.2.2 现状（证据：仓库 clone 审查，2026-09-12）

- 技术栈：**Vue 3 + TypeScript + Element Plus + Pinia**，`peerDependencies` 为 `vue ^3.5`、`element-plus ^2.13`、`@element-plus/icons-vue ^2.3.0`、`vue-i18n ^11.0.0`。**不是 React 组件库，在 React 项目中无法 import 使用**（不是功能不足，是栈不兼容）。
- 定位：统一后台应用框架/模板，从 sanqikai（Sequoia-X）前端提炼，含「组件库产物」与「应用模板」两种交付形态。
- **自研导出组件仅 13 个**（库入口 `src/components/MyUI/index.ts`）：
  `MyPageHeader`、`MyFilterBar`、`MyDataTable`（配 `usePagination`/`useTableQuery`）、`MyStatCard`、`MyStatusTag`、`MyResultState`、`MyIcon`/`MyIconButton`、`MyMenuTreeEditor`、`MyRow`/`MyCol`（12 列栅格）、`DashboardGrid`/`DashboardCell`。
  此外仅导出 icon 注册表、i18n 词条安装函数与若干类型。
- 本项目大量需要的 Dialog/Modal、Toast(Message)、Switch、Select、Input、Tabs、Tree、Slider、Tooltip 等**均不在 myui 导出面内**——Vue 形态下由消费者直接按需引入 Element Plus；myui 提供 `element-theme.scss` 玻璃化令牌覆盖。
- 主题机制：`src/styles/tokens.scss` CSS 自定义属性双主题（`:root, html.dark` 默认暗色 + `html.light`），**OKLCH 色彩空间 + 毛玻璃 token**（`--glass-*`、`--glow-accent`），与本项目 `src/styles/tokens.css` 及 myshell 的 Sequoia-X 玻璃体系同源同族。
- npm/git 消费面：ESM 单文件 `dist/myui-lib.js` + `myui-lib.css`，exports 仅 `.`、`./styles`、`./package.json` 三个；tag v0.2.2 已含 dist（0.2.1 修复），git 依赖可安装但**仅对 Vue 项目有意义**。

### 1.2 myshell/docs 统一界面方案现状

- `统一界面架构设计.md`（v1.0，2026-09-12）面向 **React 18 + TS + Vite + Tauri v2**：设计令牌（补齐 `--space-1..8`、`--font-*`、`--leading-*`、`--z-*` 层级表等）→ `src/ui/` Base 组件层（~20 个受控式组件，每个 ≤300 行）→ 五区 App Shell（TabBar/Sidebar/Workbench/右侧面板/StatusBar，CSS Grid）→ `OverlayProvider` 命令式浮层 → 按域 Context + useReducer Store。**全文未提及 myui，也无任何 Vue/非 React 项目接入说明。**
- `ui-prototype/`（index.html + styles.css + app.js）为高保真视觉原型，含完整 token 数值（`--accent: #5b8cff`、暗/亮双主题、1180/920/680 响应式断点），README 明确「复用到其他软件」的方法：改令牌、保留五区信息架构与 Overlay 层、按业务增删面板。
- 方案中亦未提及 zcode-assistant，但其 4 阶段迁移路线（打地基 → 浮层与状态收口 → 巨石拆解 → 令牌全覆盖）与本项目现状完全对应。

### 1.3 本项目现状

- React 18 + TS + Vite + Tauri v2，无路由库、无状态库、无 UI 组件库、无 tailwind。
- 已有同源 Sequoia-X 液态玻璃 token 体系（`src/styles/tokens.css`，OKLCH，`[data-theme]` 切换）与 `za-*` 全局 CSS class 体系（`.za-btn/.za-panel/.za-modal/.za-switch` 等，CSS 类而非 React 组件）。
- React 通用组件很少（仅 `DualRing`、`Progress`、`Switch`、`Toast`、`RestartBar`、icons）；10 个视图大量 inline style（Models 单文件 3838 行 / 233 处内联，Beautify 60 处，Projects 48 处，Settings 43 处），模态框在 Models 内手写了 5 个。
- 三个 Tauri 窗口：main + `float-ball`（64×100×112 透明置顶球）+ `float-panel`（280×300 面板），跨窗口 hover 联动靠 `float://` 事件总线；配额数据主窗口 5s 轮询后经 `quota://updated` 广播。

## 2. 两条路线对比：迁 Vue 3 + myui vs 留 React + docs 方案

| 层级 | 留 React，按 docs 建 `src/ui/` | 迁 Vue 3 + myui |
|---|---|---|
| 设计令牌层 | 对齐 docs 补齐（间距/字号/z-index/语义色），现有 OKLCH 体系同源，改动小 | **等价**——令牌是纯 CSS 变量，跨栈通用，是当下就能统一的部分 |
| 基础组件层 | 自建 ~20 个受控式 Base 组件（docs 第 5 节已给完整规格：Button/Input/Select/Dialog/ConfirmDialog/Toast/Toggle/Slider/Tabs/Tree/Panel/Badge/EmptyState/Spinner 等） | Element Plus + myui 13 组件；EP 体量大，需 `element-theme.scss` 玻璃化覆盖才贴合桌面玻璃风；myui 增量仅 PageHeader/FilterBar/DataTable/StatCard/StatusTag/ResultState/栅格等 |
| 应用层（10 视图） | 绞杀式渐进替换，按 docs 4 阶段走，每步可验收、可回退、零功能破坏 | **全量重写**（前端约 1.5~2 万行 TS/TSX，含 Models 3838 行单文件） |
| 悬浮球/多窗口 | 本地保留自研（myui 无此层能力） | 同样本地保留，且随重写再实现一遍 |
| 后端集成回归 | 渐进，无集中回归风险 | 117 个 Tauri 命令、窗口拖拽、跨窗口 hover 联动、`quota://` 事件桥全部回归 |
| 与统一方案文档的关系 | 与 `统一界面架构设计.md` 完全一致 | 方案文档作废，需另写 Vue 版规范 |
| 对「统一」目标的贡献 | 可与 myshell 直接共享方案/规格 | myui 现状连 myshell 自己（React）都服务不了，统一无从谈起 |

**结论：差别很大，且两条路不对称。** 迁 Vue 是「以周计的全量重写 + 高回归风险」，换来的 myui 实际增量很小（13 个组件 + 令牌层）；留在 React 是「渐进可回退」，且与方案文档零偏差。「用 myui 统一」的真正前提不是本项目迁 Vue，而是 **myui 先长出 React 发行版**。

## 3. myui 能力缺口清单（供框架更新参考）

按优先级排列：

1. **P0 — React 发行版**。建议 monorepo 双栈：`packages/tokens`（共享）+ Vue 版（现状）+ React 版。React 版 `peerDependencies: react ^18`，exports 增加 `./react`。组件规格可直接照抄 myshell/docs《统一界面架构设计.md》第 5 节的受控式 Base 清单。
2. **P0 — 组件面缺口**（myui 现有 13 组件之外，本项目 + docs Base 清单所需）：
   `Button`（variant: primary/secondary/ghost/danger; size; loading）、`Input`/`TextArea`（label、必填星号、错误态）、`Select`（模糊搜索、键盘导航）、`Dialog`（受控开关、防误关遮罩选项、Esc、焦点陷阱）、`ConfirmDialog`（danger 模式）、`Toast`（success/error/info，顶部居中，队列）、`Toggle`、`Slider`/`NumberField`、`Tree`、`Tabs`/`SegmentedControl`、`Panel`/`Section`/`FieldRow`、`Badge`/`StatusDot`、`EmptyState`、`Spinner`/`ProgressBar`、`Tooltip`、`Drawer`、命令面板（Ctrl+K）、`ColorPicker`（本项目 Beautify 换肤用）。
   **React 版不能依赖 Element Plus**：建议 headless 自建或基于 React 无头库，保持 docs 的「受控式、每组件 ≤300 行、只消费令牌」约束。
3. **P1 — 令牌独立发行**：`myui/tokens`（或 `@myui/tokens`）纯 CSS 变量包，不绑 Vue/React。这样所有项目（含 React 的 myshell 与本项目）**立即可接入令牌层统一**，不必等组件层。
4. **P1 — 桌面/Tauri 特化**：透明/无框窗口场景（悬浮球 64px 最小组件形态）、跟随系统深浅色（`prefers-color-scheme`）、CSP 约束（禁止运行时 CSS-in-JS，与 docs 原则一致）。
5. **P2 — 生态解耦**：`vue-router`/`pinia`/`vue-i18n`/`echarts` 目前是 myui 的 dependencies；React 版需剥离或替换（ECharts 封装可保留为可选 peer）。

## 4. 本项目不适用统一框架、需本地自研保留的功能

以下能力不进任何统一组件库，保留在项目内：

- **悬浮球 + 悬浮面板**（`src/windows/FloatBall.tsx` / `FloatPanel.tsx`、`src-tauri/src/float_ball.rs`）：Tauri 多窗口、透明无框、置顶、拖拽（`startDragging`）、`float://ball-leave` / `float://panel-pinned` 跨窗口 hover 联动、260ms 单双击判别。

- **Tauri 事件桥 + 配额轮询**：主窗口 5s 轮询唯一数据源，`quota://updated` 广播给悬浮窗/托盘。

## 附录 A：组件能力缺口矩阵（2026-09-12 全量清点，供 myui 补能力）

清点范围：`src/styles/*.css`（za-/fb-/fp- 全部类）、`src/components/`（13 组件 props 签名）、10 个视图内部私有组件与交互模式、悬浮窗。用途：myui 补能力时的组件矩阵与 API 要求。

### A.1 结论概览

本项目重构共需 **22 类 UI 原语**；myui v0.2.2 导出面**可直接覆盖 6 类**（StatCard、DataTable、FilterBar、StatusTag、ResultState、PageHeader+栅格），**缺 16 类**。另有 4 项行为级要求与 5 项应保留本地的业务件。

### A.2 myui 已覆盖（React 版对齐 API 即可）

| myui 组件 | 本项目消费场景 | React 版 API 要求 |
|---|---|---|
| `MyStatCard` | Dashboard StatCard（icon+label+大数值+hint） | 需补 **loading / error / empty 三态** props（Dashboard 173-187 现有此语义） |
| `MyDataTable` | Usage 明细表、Projects 会话表（同一套 `za-usage-table`） | 需支持：**纯前端排序**（表头点击 asc/desc 箭头）、**勾选列 + 表头全选/半选（indeterminate）**、单元格省略号（max-width）、**表格内占比条 cell**（`za-usage-bar` 124×18 mono 数字叠加） |
| `MyFilterBar` | Usage 过滤器（分段预设+日期范围+3 个下拉+同步按钮）、AutoSwitch 筛选 | 需支持：**预设分段按钮组**（今天/7天/30天/全部/自定义）插槽、自定义日期范围（`input[type=date]`×2）、按钮 busy 文案 |

### A.3 myui 缺失组件（需新增，按优先级）

**P0 —— 高频且影响统一性的核心件：**

1. **Button**（~60 处）：variant `primary / secondary(ghost) / danger / sm`；`size`、`icon`、**`loading`（busy 文案替换，项目里 ~15 处「刷新中/同步中/重启中」）**。注意：`.za-btn-danger` 已定义但 Projects/Accounts 用内联 `#e5484d` 绕过——统一后需强制走组件。
2. **Dialog/Modal**（两套手写模式共 13 处）：受控 open；**遮罩点击可配**（StatsConsent=遮罩即拒绝、UpdateNotification=禁点遮罩、其余=可关）；**Esc 关闭 + focus trap + body 滚动锁定**（现状全缺，仅 StatsConsent 有 Esc）；**尺寸两档**（轻 360px 确认卡 / 重 680px×86vh 表单弹窗）；**嵌套支持**（Models 拉取模型二级弹窗）；header/body/footer + **弹窗内错误横幅**（Models:3625）。
3. **ConfirmDialog**（danger 确认 ≥6 处，现状 3 种混杂：原生 `window.confirm`、行内两段式、Modal footer danger 按钮）：需 Promise 式 `confirm({...})` API + danger 变体 + 可选二次确认。
4. **Toast/Message**（135 处调用：error 71 / success 49 / warning 15）：模块级全局函数 API 正确；**补 `info` 类型**；保留本项目现有亮点：**队列上限 5、hover 暂停计时、复制消息按钮**；补可选 `duration` / `action`。
5. **Input / TextArea / Select + Field 包装**：Field 需 label/hint/**unit 后缀**/error（`field` 内联样式在 5 个视图重复定义；ZcodeSettings 全部数字字段带单位、留空=跟随默认语义）；Select 需 **optgroup 分组**（Models 预设下拉）；Input 需 **password 显隐切换（reveal）**、**mono 变体**（key/数字）、密码类型。
6. **Switch**（8 处 + Models 私有 Toggle 复制品）：受控 + disabled + **`stopPropagation` 选项**（Models 复制 Toggle 的原因就是嵌套交互）。
7. **SegmentedControl**（4 处手写「按钮组+激活态」：Usage 预设组/维度组、Settings 主题/方案切换）。
8. **Tooltip**（106 处原生 `title=`，零组件实现）：轻量即可；**注意约束：backdrop-filter 元素上 fixed 定位遮罩方案失效**（WeekdayPicker 因此用 document mousedown 收起）——浮层定位需支持该场景。

**P1 —— 单视图/中频件：**

9. **Progress + Ring**（4 处重复实现：Progress.tsx、DualRing.tsx、FloatPanel 私有 Ring、托盘 canvas）：统一 API 必须支持本项目两个特殊语义——**宽度与颜色分档解耦**（`value` 控宽、`colorValue` 定色档 + warn/danger 阈值）与**双环（外/内 = 已用/剩余，null=仅底环）**；尺寸 28/52px。
10. **Checkbox**（styled，含 indeterminate）：Projects 表头全选半选、多选列表（Export/ImportPreviewModal）。
11. **Popover / MultiSelect 下拉多选**（WeekdayPicker=按钮+绝对定位 checkbox 面板 + document mousedown 收起）：可抽象为通用 Popover + 多选下拉。
12. **Slider**（原生 range 美化 + mono 数值 + suffix %/px，Beautify RangeField、Settings 透明度）。
13. **ColorField**（原生 `input[type=color]` + hex 文本 + 清除，Beautify）。
14. **NumberField**（数字输入 + 单位后缀 + hint，ZcodeSettings FIELDS 网格；可与 Field 合并设计）。
15. **InlineEdit**（Accounts 与 Projects 重复：Enter 提交/Esc 取消 + 确认/取消 icon 按钮）。
16. **可排序列表（拖拽排序）**（Models ⠿ 手柄拖拽带 gripDownRef 防误拖、AutoSwitch 行拖拽）：myui Vue 版 dependencies 已含 `sortablejs`，React 版需对应封装。

### A.4 行为级要求（React 版组件库的横切约束）

1. **受控式 API**（docs 第 5 节规则），Base 组件只消费令牌。
2. **浮层统一走 `--z-*` 层级令牌**（docs 4.3 表）+ Portal；**禁止运行时 CSS-in-JS**（CSP 约束）。
3. **透明窗口兼容**：悬浮球/面板上下文**禁 backdrop-filter、禁外 box-shadow**（float.css 头注释约束）——浮层/卡片组件需提供「非玻璃降级」形态；暗色默认、`data-theme`/`html.dark` 两种切换约定需与消费端对齐（本项目用 `[data-theme]`，myui 用 `html.dark/light`，**需统一或双支持**）。
4. **零强依赖**：不强制 vue-i18n 等价物（本项目纯中文）、不绑 router/store；ESM 单产物 + `./styles` 入口保持现状形态。

### A.5 保留本地、无需进 myui 的业务件

- 悬浮球/悬浮面板全套（拖拽、260ms 单双击判定、跨窗口 hover 事件总线）。
- `useAppearance` 运行时换肤注入、FrostedPreview/ThemeCard（Beautify 业务预览件）。
- react-markdown 更新日志渲染（AboutDialog；React 生态件，myui 无需对等物）。
- RestartBar、UpdateNotification/AboutDialog 的 4 阶段更新状态机（业务流程，外壳用统一 Dialog 即可）。
- icons.tsx 26 个线性图标（可平移进 myui `iconRegistry`，或保留本地注册）。

## 附录 B：myui v0.5.0 复评（2026-09-12 第二轮，组件能力对照）

> 背景：框架侧按附录 A 清单更新至 v0.5.0（tag 已验证存在，dist 随 tag 分发，git 依赖可安装）。本轮对源码做行为级核对，回答「完整迁移到 myui，组件能力是否满足」。

### B.1 总评

**组件能力：基本满足。** 附录 A 所列 16 个缺口已补 ~14 个（Button/Dialog/ConfirmDialog/Toast/Toggle/Segmented/Tree/Tabs/Panel/Section/FieldShell/FieldRow/Badge/StatusDot/Spinner/Progress/Slider/NumberField/Drawer/CommandPalette 均已进导出面），并额外带来 NotificationBell、SignalTrack。**但「完整迁移」仍不成立，卡点不再是组件数量，而是：① 仍无 React 发行版（0.5.0 官方文档明示「React 版本属于独立交付物，需另行立项，不随本包分发」）；② 剩 8 个库级缺失组件 + 一批行为参数；③ 3 项横切约束未对齐。**

### B.3 仍缺清单（建议进 myui 0.6.0）

**组件（8 个）**：MyTooltip、MyCheckbox（含 indeterminate）、MyPopover（+多选下拉面板，WeekdayPicker 场景）、MyColorField（Beautify 换肤）、MyInlineEdit、MySkeleton、MyDualRing（双环进度，悬浮球核心）、拖拽排序列表封装（导出 useSortable 或 MySortableList）。

**行为参数（现有组件补 prop）**：
- MyProgress：`colorValue`（颜色档与宽度解耦）+ `warnAt/dangerAt` 阈值；
- MyNumberField / MySlider：`unit` 后缀；
- MyDialog：错误横幅形态（或 error slot）+ 宽度档位；header 插槽；
- toast：队列上限、action 按钮、hover 暂停（本项目 135 处调用的既有体验基线）；
- MySelect：options 支持分组字段（group）；
- MyStatCard：error/empty 态；
- MyInput：mono 等宽变体。

**横切约束（3 项）**：
1. **React 发行版**——唯一硬阻塞。Vue 版行为规格可作移植蓝本（受控式、overlay 命令式 API 形态都符合附录 A.4）。
2. **主题约定**：仅支持 `html.dark/html.light`，不支持本项目在用的 `[data-theme]`。二选一：myui 加 `[data-theme]` 双支持，或本项目 useTheme 迁移到 class 切换（改动小，但 tokens.css 选择器需同步调整）。
3. **令牌与浮层**：`--space-*` 是 SCSS 编译期常量非 CSS 变量（运行时换肤覆盖不到间距；本项目换肤只覆盖颜色，影响可控）；**无 `--z-*` token**（层级硬编码）；浮层全线 backdrop-filter 玻璃、**无非玻璃降级开关**（唯一途径是不引 element-theme）——透明窗口（悬浮球/面板）场景仍需自建非玻璃形态。

### B.4 结论

以「组件能力」口径：**22 类原语中完全满足 ~13、部分满足 ~6、缺失 8**——满足率约 75%，继续按 B.3 清单补一版（0.6.0）即可达到「组件能力满足」。以「完整迁移」口径：**仍不满足**，硬阻塞是 React 发行版未立项；该项落地前，本项目任何 `pnpm add myui` 的重构路线都无法执行。建议：① myui 侧按 B.3 推进（React 立项优先）；② 本项目侧可先做与栈无关的令牌层地基（附录 B.3 横切第 2 项的主题约定需先定方向）。

*本报告仅评估，未改动任何代码与依赖。*
